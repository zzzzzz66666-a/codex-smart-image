# 发布与隐私流程

用户授权发布后，先确定仓库和可见性。本项目公开分发不包含服务地址、Key 或本机账户信息。只在干净目录创建首次提交，不把含私密信息的旧历史带入公开仓库。

1. 选择插件相关源码、测试、脚本、文档和安装 Skill。保留原本地运行配置，不上传配置目录、日志、请求记录或生成图片。
2. 审查常量、示例、测试、文档、Git 身份和生成文件。服务 URL 由安装用户本地输入。将特定私有域名、姓名和本机路径放进仅本地 denylist；该文件自身不得发布。
3. 使用 scripts/check_release_privacy.py 检查候选源码；--denylist-file 接收本地 JSON 字符串列表，只输出命中位置和类别，不输出匹配值。
4. 运行完整测试、隔离安装/升级/卸载检查；更新 docs/VALIDATION.md，分别记录本地替身和真实服务验收。
5. scripts/build_release.py 从允许的文件类型和目录构建新 ZIP、AI 安装 Skill ZIP 与 SHA256，检查压缩包内部。不要复用旧版本 ZIP。
6. 审查 git ls-files 中的所有文件、暂存 blob、提交内容和作者/提交者元数据；匿名发布使用通用作者，不把私人 Git 邮箱写入提交。后续清理工作区不能消除已经上传的旧提交泄露。
7. 推送到已授权仓库并创建 Release；从远端回读提交、可见性与附件摘要，核对本地哈希。任何扫描失败都先修复，不推送有问题内容。
8. 交付给人看的指南和给 AI 的安装 Skill；按用户指定目录保存副本，校验字节/SHA256，不覆盖同目录其他产品文件。复制到沙箱外遵守权限审批。

扫描器是有界的检测辅助，不能证明所有个人信息已自动识别。必须结合目标文件人工审阅和本地私有 denylist。不要把包含命中值的完整日志、GitHub 令牌或权限诊断信息加入仓库。
